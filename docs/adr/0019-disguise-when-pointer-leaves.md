# ADR-0019：摸鱼遮罩（指针离开面板时伪装成普通编辑器窗口）

- 日期：2026-10-21
- 状态：已实现（0.19.1）
- 相关文档：ADR-0017（菜单安全边界）、ADR-0018（图片右键菜单）

## 需求

内嵌浏览器停在侧边栏 / 编辑区时，论坛、视频之类的页面会被路过的人一眼看到。
要求：**鼠标离开窗口时，把面板伪装成一个普通的 IDE 窗口**；鼠标移回来立即恢复。

## 决策

面板里加一层 [DisguisePanel]：用当前编辑器配色方案自绘「文件名页签 + 行号槽 + 一段假 Kotlin 代码」。

触发条件（纯逻辑在 [DisguisePolicy]，可单测）：

| 输入 | 作用 |
| --- | --- |
| 指针在面板外 | 必要条件 |
| 指针至少进过面板一次（armed） | 防止「切到该标签页就被盖住」 |
| 没有右键菜单 / 弹出菜单在用 | 防止遮罩浮在菜单背后 |
| 「在外」持续 ≥ 200ms | 过滤「扫过去拿个东西」的瞬时离开（数值见文末修订） |

轮询间隔 100ms；面板不可见（标签页没选中 / 工具窗收起）时不遮也不累计时间。

## D1：为什么用轮询而不是 MouseListener

- Swing 的 `mouseExited` 在**指针进入子组件时也会在父组件上触发**，面板里全是子组件（工具栏、
  地址栏、JCEF），靠它判断「是否在面板内」必须自己再算一遍坐标。
- JCEF 是 OSR 组件，页面内的指针交互发生在 CEF 侧，Swing 根本收不到 enter/exit。

所以直接用 `MouseInfo.getPointerInfo()` + `SwingUtilities.convertPointFromScreen` 每 100ms 判一次
「指针在不在 root 的矩形内」。100ms × 一次坐标换算的代价可以忽略，而「移回立即恢复」的观感也够。

## D2：为什么用 CardLayout 双卡 + 隐藏工具栏/状态栏

面板是 `root`（`BorderLayout`：工具栏 NORTH、内容 CENTER、状态栏 SOUTH）。要盖住工具栏与地址栏
（否则一眼就能看到 URL），最初的想法是「把遮罩也 add 到 CENTER」——**这个前提是错的**：
`BorderLayout` 的 CENTER 是单槽字段，同一约束加两个组件时只有最后加入的那个能拿到边界，
前一个留在 `root.components` 里但永远停在 0×0。

后果不是「遮罩盖不住」，而是**浏览器被彻底废掉**：JCEF 组件的 `width == 0`，
`ensureKernel()` 的尺寸检查直接返回，内核永远不会创建（评审 B1 发现的阻断项，
构建与单测都检不出来，只有读代码能发现）。

最终做法：

- `root.CENTER` 放一个 `CardLayout` 宿主 `centerHost`，「网页」与「遮罩」是两张卡，切卡即可；
- 遮住时另外把 `root` 的其它子组件（工具栏、状态栏）`isVisible = false` 并记录原值，解除时原样恢复；
- 遍历 `root.components` 时必须排除 `centerHost`，否则会把承载遮罩的宿主一起藏掉。

## D3：为什么菜单要抑制遮罩

CEF 的右键菜单在面板区域之外（尤其 IntelliJ 用 Swing 弹出菜单实现时），指针必然「在面板外」，
200ms 后遮罩就会浮到菜单背后 —— 看起来像功能坏了。因此：

- `ImageMenuHandler.onBeforeContextMenu` 置位 `contextMenuOpen`，
  `onContextMenuDismissed` 复位；
- 同时用 `MenuSelectionManager.selectedPath` 覆盖书签这类 Swing 弹出菜单；
- 置位带 2 分钟上限：万一复位回调没来，也不能让遮罩从此永久失效；但又不能太短，
  否则「菜单慢慢翻超过 2 分钟」会反过来把遮罩盖到菜单背后；
- 这两个字段跨线程（CEF 写 / EDT 读），因此 `@Volatile`，且写入顺序固定为
  「先时间戳、后标志」—— 否则 EDT 可能读到 `(true, 0)` 并立刻按超时复位。

## D4：伪装成什么样子

用 `EditorColorsManager.globalScheme` 取背景/前景/关键字/字符串/数字/注释色与等宽字体，
自绘一条文件名页签（`TaskScheduler.kt`）、行号槽、一段固定假代码，并高亮其中一行模拟光标行。
这样浅色 / 深色主题都跟 IDE 一致，不需要维护两套配色。

刻意**不**做成可编辑控件（`JTextArea`）：遮罩只需要「看起来像」，不需要光标、选区、滚动条，
引入可编辑控件反而会抢焦点、被误触。

## D5：开关

工具栏右侧新增「伪装开 / 伪装关」按钮（文案等宽，切换时不跳）：

- 状态存 `PropertiesComponent`（键 `monkeyBrowser.disguiseEnabled`，默认**开**），
  跨标签页、跨会话共享 —— 遮罩是「别被看到」的安全网，不适合每个标签页各配一份；
- 关闭时**立即**恢复页面（不等下一个 tick），并取消武装：重新打开后要求指针先进面板一次，
  避免「刚打开开关、指针恰好在面板外」时立刻被盖住；
- 其它标签页的面板在各自的下一个 tick（≤100ms）读到新状态并刷新按钮，不需要消息总线；
- 关掉后 tick 早退，不再碰 `MouseInfo`，也不累计任何计时。

## 验证

- `DisguisePolicyTest`（3 项）：触发条件真值表（在外/武装/菜单/开关四者的唯一允许组合）、
  200ms 延迟边界（差 1ms 不遮、时钟回拨不遮）、轮询间隔与延迟的合理范围。
- **接线部分（CardLayout 切卡、可见性快照、定时器启停、CEF 重推尺寸）没有单测**：
  它依赖真实 Swing 层次与 JCEF 内核，只能在 IDE 里手工验证。这一点如实记录，不写成「已验证」。
- 手工验证清单（安装后）：
  1. 鼠标移进浏览区 → 再移到编辑器停约 1 秒 → 面板应变成假编辑器（工具栏、地址栏一起消失）；
  2. 鼠标移回面板 → 立即恢复，页面内容正常（**重点确认不是黑屏/花屏**）；
  3. 在一个有动画/视频的页面上重复 1-2，确认恢复后仍在动；
  4. 切到其它标签页再切回来 → 不应立刻被遮住（需要先把指针移进面板一次）；
  5. 图片右键菜单打开期间不应出现遮罩；
  6. 点「伪装开」→ 按钮变「伪装关」，此后指针离开面板不再遮；再点回来，需先把指针移进面板一次才会重新遮。
  日志：`[RM-BROWSER] 面板#… 已伪装…` / `[RM-BROWSER] 面板#… 伪装解除…`。

## 已知限制

1. **只要指针不在面板上就会遮**，不区分「人在不在电脑前」：把鼠标停在别处看网页正文时，
   面板会被盖住（移回即恢复）。这是需求本身的形状，不是缺陷；如果嫌吵，只能加「手动开关」。
2. **切换标签页后需要先把指针移进面板一次**（armed）。否则切过去就被盖住，更莫名。
3. **没有快捷键**：只有工具栏开关（D5）；要做快捷键得先定作用域（全局 / 仅焦点在浏览器时），本批不做。
4. **遮罩期间 JCEF 组件只是不可见，CEF 并不知道**：没有人调用 `wasHidden`，内核仍在渲染
   （所以「CSS 动画会暂停」的说法不成立）。代价是恢复后要靠主动重推尺寸
   （清掉同尺寸去重后 `schedulePushSize`）让 OSR 重画；这条路径**未经手工验证**，
   若出现恢复后黑屏/花屏，问题就在这里。
5. **判定用的矩形是 `root` 的屏幕矩形**：面板被别的窗口遮住时指针仍可能落在矩形内，
   此时不遮 —— 这种情况本来也看不到面板，不算问题。
6. **只盖面板本体**：标签页标题（`JBTabs` 的 tab 文案）与工具窗标题仍是网页标题
   （标题来自 `onTitleChanged`，属于容器而非面板），遮罩管不到。
7. **不支持「手动开启/关闭」**：判定只有自动的三种抑制条件；要临时不遮，把指针移进面板即可。

## 修订

- **2026-10-21：延迟 800ms → 200ms，轮询 250ms → 100ms。**
  用户反馈「要等近一秒才盖」太慢。原值是保守的抗抖动取值；调快后实际观感 0.2～0.3 秒，
  代价是「指针离开 200ms 以上又回来」会看到一次遮罩闪现。数值集中在 `DisguisePolicy`
  两个常量里，要再调只改这两处。
