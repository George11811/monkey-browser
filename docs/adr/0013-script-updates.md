# ADR-0013：脚本更新检查（`@updateURL` / `@downloadURL`）

- 日期：2026-10-13
- 状态：已实现（0.15.0）
- 相关文档：ADR-0004、ADR-0005、方案 §1.2 的 P2「自动更新」

## 结论与本实现的偏离

方案 P2 写的是「自动更新」。本实现刻意做成 **「按需检查 + 用户确认后应用」**，原因如下：

1. `@updateURL` 是**外部地址**。IDE 启动时静默联网既不可预期（用户不知道谁在联网），
   也会拖慢启动；脚本多时更明显。
2. 更新会**覆盖用户磁盘上的脚本文件**。静默替换的代价不对称：更新成功用户无感，
   更新失败（远端被改坏、指向别处、或被中间人篡改）用户会直接失去可用脚本。

所以：**联网与写盘都必须由用户显式触发**。如果将来要做定时检查，也应当只做「检查并提示」，
不自动写盘。

## D1：`@updateURL` 与 `@downloadURL` 的分工

Tampermonkey 允许 `@updateURL` 指向**只含元数据块**的文件（约定后缀 `.meta.js`），
脚本正文放在 `@downloadURL`。因此：

```text
版本判断  -> 拉 @updateURL，解析元数据块，取 @version
正文获取  -> @downloadURL（未声明则回落到 @updateURL）
```

**安全要点**：如果两个地址相同、且远端**只有元数据块没有正文**，绝不能写盘 ——
那会把用户的脚本替换成一个空壳。这种情况返回可读错误，明确提示「应提供 `@downloadURL`」。

## D2：版本比较单独成对象

`ScriptVersions.compare` 是纯函数，独立于网络与 UI，因此可以直接单测 —— 它是整个功能里
唯一容易写错、又最容易**悄悄**写错的部分：`1.10` 与 `1.9` 按字符串比会得出**相反**结论
（这正是测试里专门覆盖的一条）。

规则（简化实现，不是完整 semver）：

- 按 `.` / `-` / `_` 分段；两侧都是数字就按**数值**比，否则按不区分大小写的字典序。
- 段数不等时补空段，并约定：**数字段 vs 空段 = 数字段更新**（`1.2.1 > 1.2`）；
  **非数字段 vs 空段 = 非数字段更旧**（`1.0-beta < 1.0`，与预发布约定一致）。

不覆盖 `build.5` 这类带前缀的段语义，也不做完整 semver 校验 —— 目的是「远端是不是更新了」，
不是严格排序。

## D3：写盘前先备份

应用更新时先把旧文件复制为 `<文件名>.user.js.bak`，再写新内容。

选这个位置而不是另建备份目录，是因为 [ScriptFileStore.load] **只收集 `*.user.js`**，
`.user.js.bak` 不会被当成脚本读入（已核对 `load()` 的 `newDirectoryStream(scriptsDir, "*.user.js")`）。
同一个脚本只保留**一份**上一版，不会无限堆积，且用户能直接看到、手工还原。

## D4：入口与错误呈现

- 脚本管理面板新增第 5 个图标按钮（`AllIcons.Actions.Download`，字段已用 `javap` 核实存在），
  并在右键菜单里提供同一入口（与「编辑 / 移出 / 打开目录 / 刷新」的既有做法一致）。
- 网络请求走平台线程池，**不占 EDT**；结果回到 EDT 后用对话框呈现。
- 没有任何脚本声明 `@updateURL` 时直接给出可读提示，不发请求。
- 应用后刷新脚本库并重载所有标签页，让改动立刻生效。
